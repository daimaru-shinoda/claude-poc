# gas-hikiwatashi-checker 実装仕様書

## 1. ゴール

引渡予定報告書（スプレッドシートA）と引渡のお知らせ 営業⇔総務（スプレッドシートB）の整合性を自動チェックし、不一致を LINE WORKS のチャンネルに通知する Google Apps Script プログラム。

スプレッドシートAの確定済み物件に対して「スプレッドシートBに対応行がない」または「引渡日が食い違う」ものをエラーとして検出し、担当者に早期通知することを目的とする。

## 3. スプレッドシートの仕様

### 3-1. 引渡予定報告書（スプレッドシートA）

- **スプレッドシートID**: `1qTMPzXOGFM7202XOb9UPBgh6lLJYwquu50V8CDPBcw4`
- **対象シートの選び方**: 全シートの中でシート名が `/^\d{2}期.+\d{2}期$/` にマッチするものの**最後のもの**（最新期）を使用。見つからなければ例外をスローする。
- **ヘッダー行**: 4行目（1〜3行目は別用途のため読み飛ばす）

| 列名 | 用途 |
|---|---|
| `物件名` | 物件の識別キー（正規化後に使用） |
| `担当者` | 担当営業の名前（通知メッセージに使用） |
| `顧客名` | 顧客の名前（通知メッセージに使用） |
| `引渡日` | `yyyy/MM/dd` または `yyyy-MM-dd` 形式の文字列 |
| `引渡日確定` | `"確定"` の行のみチェック対象 |

**フィルタ条件**:
- `引渡日確定` 列が `"確定"` と完全一致する行のみ
- `引渡日` が基準日（実行時刻）の **-20日〜+3日** の範囲内
- `引渡日` がパース不能な場合はその行をスキップ

**重複行の扱い**: 同じ物件名が複数行ある場合は**下の行で上書き**する（後から追加された行が最新データのため）。

### 3-2. 引渡のお知らせ 営業⇔総務（スプレッドシートB）

- **スプレッドシートID**: `1ozrZZ-7bJtlIoaZnWs-PrgMs2jKqxgfbkSg1af8pDcU`
- **対象シート名**: `"引渡のお知らせ　営業⇔総務"`（「営業」と「総務」の間は**全角スペース**）
- **ヘッダー行**: 1行目

| 列名 | 用途 |
|---|---|
| `お名前` | 顧客名（空欄行はスキップ） |
| `引渡日` | `yyyy/MM/dd` または `yyyy-MM-dd` 形式 |
| `現場名` | 物件キー生成に使用 |
| `区画` | 物件キー生成に使用（`現場名 + 区画` を正規化） |

**物件キーの生成**: `fixName(現場名 + 区画)`

**重複行の扱い**: 同じ物件キーが複数行ある場合は**最初のデータを使用**（後から出てくる行は古いデータのため無視）。スプレッドシートAとは逆の扱い。

## 4. ビジネスロジック

### 4-1. チェックルール

スプレッドシートAの確定済み物件ごとに以下を判定する:

1. 対応する物件キーがスプレッドシートBに**存在しない** → お知らせ未作成エラー
2. 存在するが**引渡日が異なる** → 日付不一致エラー

### 4-2. 物件名の正規化ルール（`fixName`）

両スプレッドシートで同じ変換を適用してキー比較する。以下を順番に適用:

1. 全角英数字を半角に変換（`Ａ-Ｚ`、`ａ-ｚ`、`０-９` → 半角）
2. 半角・全角スペースを除去
3. 末尾の「棟」を除去
4. 末尾の「区画」を除去

### 4-3. 日付の取り扱い

- `yyyy/MM/dd` と `yyyy-MM-dd` の両形式を受け付ける
- 内部では `Date` オブジェクトに変換してから比較する（文字列比較ではない）
- 保存・送信時は `yyyy/MM/dd` 形式に統一する
- パース不能（空文字、パーツが3つでない、数値変換後に0になる）の場合は `null` として行をスキップ

### 4-4. ヘッダーセルの注意点

スプレッドシートAのヘッダーセルは改行を含む場合があるため、列名照合前に改行除去とトリムを行う。

## 5. 通知仕様

### 5-1. 正常時

通知なし。`console.log("チェック完了: エラーなし")` のみ。

### 5-2. エラーあり時

LINE WORKS のチャンネルにメッセージを送信する。複数エラーは `"\n\n"` 区切りで1メッセージに結合。

```
引渡のお知らせ　営業⇔総務 で問題のありそうな物件がありました

[お知らせ未作成の場合]
{customerName}様の 引渡のお知らせ　営業⇔総務 が作成されてません。
引渡日: {date}、担当: {sales}、物件名: {bukkenmei}

[引渡日不一致の場合]
{customerName}様の 引渡予定報告書と引渡のお知らせ　営業⇔総務 の引渡日が違うようです
担当: {sales}
```

### 5-3. テストモード

Script Properties の `TEST` が `"true"` のとき:
- 送信先を `LINEWORKS_TEST_CHANNEL_ID` に変更する
- メッセージ冒頭に `"このメッセージはテストに流れてます\n"` を付加する

### 5-4. リトライ

`lineworks.postMessage` は最大3回リトライする。リトライ間隔は `i * 3000ms`（1回目失敗後3秒、2回目失敗後6秒）。3回すべて失敗したら最後の例外をスローする。

---

## 6. Script Properties 一覧

GAS の「プロジェクトの設定」→「スクリプト プロパティ」から設定する。いずれかが未設定の場合は例外をスローして処理を中断する。

| キー | 説明 |
|---|---|
| `TEST` | `"true"` のときテストモードで動作する |
| `PRIVATE_KEY_FILE_ID` | LINE WORKS サービスアカウントの秘密鍵ファイルの Google Drive ファイルID |
| `LINEWORKS_CLIENT_ID` | LINE WORKS Developer Console の OAuth Client ID |
| `LINEWORKS_CLIENT_SECRET` | 同 Client Secret |
| `LINEWORKS_SERVICE_ACCOUNT` | サービスアカウントのメールアドレス形式 ID |
| `LINEWORKS_BOT_ID` | Bot の数値 ID |
| `LINEWORKS_TEST_CHANNEL_ID` | テスト用チャンネルの ID |
| `LINEWORKS_HONBAN_CHANNEL_ID` | 本番用チャンネルの ID |
