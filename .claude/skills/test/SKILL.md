# test skill

## 目的

プロジェクトの言語・フレームワークを自動検出して、適切なテスト手段にディスパッチする。

## 実行手順

### Step 1: 言語・フレームワーク検出

検出は **2 段階** で行う:

**1-A. 専用テストスキル（`test-*`）のディスパッチ判定**

各言語専用のテストスキルは `.claude/skills/test-{言語名}/` に配置されており、検出条件を自分の SKILL.md 内に持つ。test スキル本体はその情報を動的に読み取って判定する。

手順:

1. `.claude/skills/test-*/SKILL.md` を Glob で列挙する（このスキル自身の `test/SKILL.md` は除外）
2. 各 SKILL.md の `## 検出条件` セクションを Read する。各セクションには以下が記載されている前提:
   - **優先度**: 整数値（数値が大きいほど優先）
   - **マーカーファイル**: プロジェクトルートからの相対パスのリスト
3. 各スキルについて、マーカーファイルが 1 つでもプロジェクトに存在するか Glob で確認する
4. マッチしたスキルを「候補リスト」に入れる
5. 候補が複数ある場合は **優先度の高いもの** を選択する。同じ優先度なら最初に見つかったものを選ぶ
6. 選択したスキルを Skill ツールで呼び出す

候補が 1 つも見つからなかった場合は 1-B へ進む。

**1-B. 汎用フォールバック（専用スキル不在の言語）**

専用 `test-*` スキルがマッチしなかった場合、組み込みの言語マーカーで判定する:

| 検出ファイル | アクション |
|---|---|
| `package.json`（`scripts.test` あり） | `npm test` を実行 |
| `package.json`（`scripts.test` なし）かつ `tests/test.js` がある | `node tests/test.js` を実行 |
| `pytest.ini` / `pyproject.toml`（`[tool.pytest.ini_options]` を含む）/ `setup.py` | `python -m pytest` を実行 |
| `go.mod` | `go test ./...` を実行 |
| `Cargo.toml` | `cargo test` を実行 |

複数の検出ファイルが存在する場合はテーブル上位を優先する。

どれにも該当しない場合は「テスト設定が見つかりません」と報告して終了する。

### Step 2: テスト実行

検出した方法でテストを実行し、終了コードと出力を確認する。

### Step 3: 結果報告

**全テスト pass の場合**:

```
テスト結果: X tests, X passed — OK
```

**テスト失敗の場合**:

```
テスト失敗: X tests, X passed, X failed

失敗したテスト:
  ✗ テスト名: エラーメッセージ
```

失敗した場合は処理を中断し、呼び出し元（/audit マスタースキル等）に失敗を伝える。

**テストファイルが見つからない場合**:

言語ごとに適切なテストスキル（例: `/test-gas`）の実行を促してから終了する。

## 新言語の追加方法

専用テストスキルを追加する場合、`/test` スキル本体は編集不要。以下の 2 ステップで完結する:

1. `.claude/skills/test-{言語名}/SKILL.md` を作成し、テスト生成・実行の手順を書く
2. その SKILL.md の末尾に `## 検出条件` セクションを追加する:

   ```markdown
   ## 検出条件

   このセクションは `/test` スキルから動的に読み取られる。

   **優先度**: 10

   **マーカーファイル**:
   - `go.mod`
   ```

優先度の目安:
- 30 以上: 他のマーカーと共存しても確実に勝たせたい強いシグナル
- 10〜20: 通常の言語マーカー
- 0〜9: フォールバック寄りの弱いシグナル

汎用フォールバック（`npm test` など）の挙動を変えたい場合のみ、`/test` 本体の Step 1-B テーブルを編集する。
